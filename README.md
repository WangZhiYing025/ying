# 明陽來村｜宅配申請表

提供顧客填寫宅配資料與方便收貨時段的行動版網頁。專案使用 GitHub Pages 發佈靜態頁面，並將申請資料送交 Google Apps Script，由後端寫入 Google 試算表。

- **線上表單：** https://wangzhiying025.github.io/ying/
- **程式入口：** [index.html](./index.html)
- **目前狀態：** 基本表單與資料送出流程已建置；後續待完成下方維護與驗收任務。

> 本頁會處理姓名、電話及宅配地址等個人資料。正式使用前，請確認資料蒐集告知、試算表存取權限、保存期限及刪除流程符合實際營運需求。不要將試算表、金鑰或管理用資料放進公開 GitHub 儲存庫。

## 專案目標

- 讓顧客以手機或電腦填寫宅配申請。
- 收集姓名、聯絡電話、宅配地址、購買物品及方便收貨時間。
- 時間選項限下午 12:00 至 17:00，並要求結束時間晚於開始時間。
- 清楚告知顧客：送貨日期確認後會以電話聯絡。
- 讓管理者透過受權限保護的 Google 試算表處理申請資料。

## 目前功能

- 單頁式中文宅配申請表，適用手機與桌面瀏覽器。
- 姓名、電話、地址、購買物品欄位及瀏覽器端必填檢查。
- 每 30 分鐘提供一次收貨時間選擇，範圍為 12:00–17:00。
- 開始時間變更時，限制結束時間必須較晚。
- 表單以 POST 送往 Google Apps Script Web App。
- 透過隱藏 iframe 接收送出後的頁面載入事件，顯示伺服器回應提示。

## 專案檔案與資料流程

```text
ying/
├── index.html   # 表單版面、時間選項、欄位檢查及送出行為
└── README.md    # 專案說明、部署方式與待辦計畫
```

資料流程：

1. 顧客在 `index.html` 填寫並提交表單。
2. 瀏覽器將欄位以 POST 傳送到 Google Apps Script Web App。
3. Apps Script 驗證資料並新增一筆到指定的 Google 試算表。
4. 網頁顯示送出回應；營運人員在受限權限的試算表中確認申請，並於送貨日期確認後電話聯絡。

GitHub Pages 只負責提供靜態網頁，不會替表單保存資料；資料接收和試算表寫入由 Apps Script 負責。前端目前以 iframe 載入狀態提示，無法可靠判定後端是否成功寫入。請先確認試算表實際收到資料，再以 Apps Script 回應改善成功與失敗訊息。

## 部署與設定

### GitHub Pages

1. 將此儲存庫的 `main` 分支推送至 GitHub。
2. 在儲存庫 **Settings → Pages** 設定從 `main` 分支的根目錄發佈。
3. 等待 GitHub Pages 完成建置，開啟上方線上表單網址確認頁面。

修改 `index.html` 並推送到 `main` 後，GitHub Pages 會更新網站。

### Google Apps Script

1. 建立或確認 Apps Script Web App，並設定寫入目標 Google 試算表。
2. 確認 Apps Script 接收的欄位名稱與表單一致：`name`、`phone`、`address`、`products`、`startTime`、`endTime`。
3. 將 Web App 部署為正式版本，設定適合的執行身分與存取範圍。
4. 確認 `index.html` 的表單 `action` 指向有效的 Web App 網址。
5. 用測試資料提交，確認試算表新增欄位正確；正式驗收前刪除測試資料。

> Apps Script 的存取設定會影響誰能提交資料。上線前請確認存取範圍、試算表分享對象和資料處理方式；不要在公開 README 放入試算表 ID、存取憑證或其他管理資訊。

## 任務規劃

### 第一階段：確認目前服務可用

- [ ] 確認 GitHub Pages 網址可開啟，手機與桌面版版面正常。
- [ ] 確認 Apps Script 部署版本、表單欄位名稱及試算表欄位對應。
- [ ] 使用不含真實個資的測試資料，驗證成功提交會新增一列。
- [ ] 確認空白必填欄位、無效電話及不合法時段會被拒絕。
- [ ] 確認 12:00、17:00 邊界和開始時間晚於或等於結束時間的情況。

### 第二階段：改善送出體驗

- [ ] 讓 Apps Script 回傳可辨識的成功／失敗結果，避免只顯示「已收到伺服器回應」。
- [ ] 送出期間停用按鈕並避免重複提交；失敗時保留顧客已填內容並提供重試方式。
- [ ] 成功送出後顯示明確確認訊息，再清除表單內容。
- [ ] 加入可見的欄位標籤、錯誤提示和鍵盤操作焦點樣式，檢查螢幕閱讀器可讀性。

### 第三階段：資料保護與營運維護

- [ ] 在表單新增個人資料蒐集用途、使用範圍、保存期限及聯絡方式說明。
- [ ] 限制試算表僅由必要的營運人員存取，定期檢查共用權限。
- [ ] 訂定申請資料保存與刪除流程，避免長期保留不必要的個人資料。
- [ ] 記錄 Apps Script 部署版本與負責維護者，並建立故障時的聯絡和處理方式。

### 第四階段：發布前驗收

- [ ] 確認正式 Web App 與 Pages 網址都使用 HTTPS。
- [ ] 在 iPhone／Android 及桌面瀏覽器各完成一次端到端測試。
- [ ] 確認錯誤時不會誤報成功，也不會因重複點擊產生重複申請。
- [ ] 移除測試資料，確認公開儲存庫沒有試算表管理資訊或存取憑證。
- [ ] 更新本 README 的功能與待辦狀態，再公告正式表單網址。

## 建議驗收條件

- 有效表單可成功寫入試算表，欄位順序與申請內容一致。
- 必填資料不完整或時段不合法時，顧客會收到可理解的提示。
- 成功及失敗回應能正確區分，表單不會把未寫入資料顯示為成功。
- 手機版可以完成填寫，所有主要欄位和按鈕可用鍵盤操作。
- 公開儲存庫沒有真實申請資料、試算表管理權限或秘密憑證。
